Quickstart

Create an application in the developer console, generate a sandbox key, then move to production when your integration is ready.

curl https://api.merveil.ai/api/v1/profile \ -H "X-API-Key: mv_test_YOUR_KEY"
Production keys begin with mv_live_. Keep them on your server. Never expose a production API key in browser, mobile, or public repository code.

Trusted identity

Safe profile, Passport and verification summaries with strict scopes. Raw identity-document evidence is never returned through the public API.

Merveil AI

Server-side AI generation with application scopes, rate limits and Passport-aware usage limits.

Applications

Create isolated sandbox and production applications. Keys are stored as SHA-256 hashes and secrets are displayed only once.

POST /api/v1/apps Authorization: Bearer <Merveil session> {"name":"My Product","environment":"sandbox","scopes":["profile:read","ai:use"]}

OAuth

OAuth client registration is available for user-delegated integrations. Redirect URIs are HTTPS-only and scopes are explicit.

Use OAuth for integrations acting on behalf of Merveil users. Use API keys for controlled server-to-server application access.

Webhooks

Register HTTPS webhook endpoints per application. Merveil issues a one-time signing secret; verify webhook signatures before processing events.

POST /api/v1/webhooks?app_id=YOUR_APP_ID Authorization: Bearer <Merveil session> Content-Type: application/json {"url":"https://example.com/webhooks/merveil","events":["connection.created","verification.updated"]}

Security

Merveil's external platform is designed around least privilege and data minimization.

Scoped access

Applications receive only the capabilities they request and users authorize.

Rate limiting

Sandbox and production applications have separate per-minute limits with standard rate-limit response headers.

Data minimization

Passport APIs intentionally exclude document numbers, document paths, date of birth and KYC evidence.
