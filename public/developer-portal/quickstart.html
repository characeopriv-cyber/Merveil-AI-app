1. Create your application

Sandbox

Use mv_test_… credentials while building. Sandbox traffic is isolated from live production credentials.

Production

Use mv_live_… credentials only from your trusted backend after integration testing.

2. Make your first request

curl https://api.merveil.ai/api/v1/profile \
  -H "X-API-Key: mv_test_YOUR_KEY"
Never put an Merveil API key in browser JavaScript, a mobile app bundle, public GitHub repository, or client-side environment variable.

3. Choose least-privilege scopes

profile:readpassport:readconnect:readconnect:writeai:usecall:readcall:writecompanies:readproperties:readworld:readinvestors:readcredits:readverification:read

4. OAuth 2.0 + PKCE

OAuth uses Authorization Code flow. PKCE S256 is supported for public clients. Confidential clients use their client secret at the token endpoint. Redirect URIs must exactly match the registered HTTPS URI.

GET https://developers.merveil.ai/oauth-consent.html?

5. Webhooks

Register an HTTPS endpoint to receive Merveil events. Store the one-time signing secret securely and verify every webhook before processing it.

6. Production checklist

Credentials

Use production keys only on your server. Rotate immediately if exposed.

Scopes

Remove permissions your integration does not use.

OAuth

Use state, PKCE S256, exact redirects, secure token storage and refresh rotation.

Webhooks

Verify signatures, reject replays, and make handlers idempotent.

7. Billing

Developer API plans are billed through Stripe worldwide checkout. A paid plan becomes active only after verified payment/webhook processing. Merveil does not expose Supabase directly to external developers.
